# Tasks

## 1. Confirm the fact the design rests on

The question "does our own bus connection receive process file descriptors?" is **answered: yes** — measured against the crate's own `connect_a11y_bus()` path on the host a11y bus (dbus-broker 37), a private `dbus-daemon` 1.16.2 and a private `dbus-broker` 37, 13 credential rows, every descriptor on `pidfs`, the self row's inode equal to `pidfd_open(getpid())`, no feature flag needed (design: Context). What remains is a short re-run in the environment this change is implemented against.

- [ ] 1.1 Re-run the credentials probe once in the target session and record the output in the change notes: for the connection's own unique name and for every registered application print whether `ProcessFD` is present, `fstatfs(fd).f_type` in hex, `fstat(fd).st_ino`, the `Pid:` line of `/proc/self/fdinfo/<fd>`, the reported `ProcessID`, and `getpid()`. Note the seam it needs: `mod connection;` is private (`crates/provider-atspi/src/lib.rs:13`), so an `examples/` target cannot use `connect_a11y_bus()` — put the probe in the crate (an in-crate test or bin) or make the module public, rather than opening a second connection path that is not the one the provider uses. Verify: descriptors arrive with `f_type = 0x50494446` and the self row's inode matches `pidfd_open(getpid())`, matching the recorded measurement. If a daemon known to send descriptors (dbus-daemon ≥ 1.16 or dbus-broker ≥ 35) sends none here, stop and report — that would be a new environment fact, not the state the design assumes.
- [ ] 1.2 Record the same output from a second daemon implementation if one is reachable locally (dbus-broker vs dbus-daemon), including one run from a sibling PID namespace, and confirm the two rows the design leans on: for our *own* connection the credentials omit `ProcessID` while `ProcessFD` is present with our inode, and `GetConnectionUnixProcessID` answers with a successful `0` on dbus-broker and `org.freedesktop.DBus.Error.UnixProcessIdUnknown` on dbus-daemon 1.16.2. Verify: the observed answers match the table in design.md, or the divergence is written down in this change before continuing.

## 3. The identity module
