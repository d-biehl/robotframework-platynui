## Why

A PlatynUI runtime does not own the platform it drives. Platform devices (pointer, keyboard, screenshot, highlight, window manager, desktop info) are `inventory`-registered `&'static` singletons, and their connections live in process-global statics gated by a reference-counted `PlatformModulesLease` (`crates/runtime/src/runtime/platform_modules.rs`). UiTreeProviders, by contrast, are already per-runtime — built fresh by a factory (`AtspiFactory::create()`), holding their connection in an instance field (`AtspiProvider.conn`). The platform layer is the odd one out, and it is broken.

The X11 connection is a `static OnceLock<Mutex<Option<X11Handle>>>` whose connect closure fires once per process (`crates/platform-linux-x11/src/x11util.rs:16`). On runtime teardown `shutdown_connection()` empties the inner `Option`, but the `OnceLock` stays initialized, so the closure never re-runs and every later runtime fails with `x11 connection: not available after shutdown or failed connect`. Because `BareMetal` is `scope='SUITE'` and builds one native `Runtime` per suite, the multi-suite `just test-acceptance-x11` lane tears the connection down and cannot rebuild it — confirmed live: **16 of 26 tests fail** once the first suite's runtime is dropped. The X11 highlight controller (`highlight.rs:48`) and the Windows highlight controller (`platform-windows/src/highlight.rs:66`) carry the identical `OnceLock` + `.take()` defect.

The fix is architectural, not a patch: make each runtime own its platform instances and release them on drop — knowing nothing about any other runtime — exactly as providers already do. This removes the whole defect class by construction and lays the groundwork for a runtime to be bound to a *specific* session (a chosen display server and accessibility bus), so that two `BareMetal` instances in one test process can drive two independent sessions. This proposal supersedes the narrow "make X11 reconnect on demand" fix recorded in the `x11-connection-cached-across-runtimes` project memory.

## What Changes

- **Per-runtime platform ownership (Rust).** Introduce a `PlatformFactory` (`id` + `can_serve(config)` + `create(config)`), mirroring `UiTreeProviderFactory`. `create` returns an owned bundle of platform devices that share one `Arc`'d connection; the `Runtime` stores the bundle by value instead of `Option<&'static dyn Device>`. On `Runtime::drop` the bundle drops, the last `Arc` closes the connection, and per-session threads (e.g. the highlight overlay) join.
- **Delete process-global platform state (Rust).** Remove `PlatformModulesLease` / `PLATFORM_MODULES_STATE` and the connection `static`s: the X11 `OnceLock` connection (`x11util.rs`), the X11 highlight controller (`highlight.rs`), and the Windows highlight controller. X11 connection / keymap / atoms and the highlight controller become owned per-instance state shared via `Arc` (the pattern `provider-atspi` already uses via `ClearableCell` + `Arc<AccessibilityConnection>`). **Fixes the X11 acceptance failure and both highlight bugs.**
- **Runtime session `config` (Rust + Python).** A new construction-time, immutable `config` dictionary threads from `BareMetal(config=…)` through the native `Runtime(config)` into a `RuntimeConfig`, fanned out to each `PlatformFactory` and each `UiTreeProviderFactory` by component id. Two buckets — `platform` and `providers` — each keyed by backend id (`platform: {backend?, x11: {display}, wayland: {…}, windows: {…}}`, `providers: {atspi: {bus_address}}`). One dict is portable across operating systems.
- **Backward-compatible defaults.** An absent or empty `config` reproduces today's behavior byte-for-byte: auto-detect the platform from the environment, AT-SPI discovers its bus from the environment. Every key is an override layered on top; environment lookups (`DISPLAY`, `WAYLAND_DISPLAY`, `AT_SPI_BUS_ADDRESS`) become "use the config value if present, else the env" — additive.
- **Tolerant resolution.** Keys or backend ids that no registered component claims — another OS's block in a portable dict, or a typo — are ignored with a debug-level log (favouring portability and forward-compatibility; the documented cost is that typos fail silent).
- **AT-SPI explicit bus (Rust + provider factory).** Because the AT-SPI bus is display-coupled, the provider factory must accept a `providers.atspi.bus_address` so a runtime can bind to a chosen session's bus instead of the process default.
- **`BareMetal` gains `config=` (Python/RF).** A separate argument from the existing scoped behavioral dicts (`query_settings`, `pointer_profile`, `keyboard_profile`), which are unchanged. `use_mock` is reconciled with `config` (kept as sugar for `platform.backend="mock"` — decided in design).
- **Documentation.** Update `dev-docs/architecture.md` (platform/runtime lifecycle), `dev-docs/platform-linux.md`, `dev-docs/python-bindings.md`, `dev-docs/python-library-design.md`, `dev-docs/testing-strategy.md` (why the X11 acceptance lane is now green), and the `BareMetal` library docstring / any `docs/` user documentation for the new `config=` argument.

Explicit non-goals (follow-up phases, recorded here so they are on the record):

- **Wayland globals internalization.** Wayland's connection + event thread (`connection.rs` `GLOBAL`), `input::BACKEND`, `desktop::OUTPUTS`, and the `platynui_ipc` window map remain process-global singletons; moving them per-instance is required for a *Wayland* runtime to be fully owned and is deferred.
- **Concurrent two-session payoff.** Actually running one X11 and one Wayland `BareMetal` instance in the same process depends on the Wayland work above.
- **`PlatynUI` → `scope='SUITE'`.** Flipping the (still-placeholder) `PlatynUI` library off `scope='GLOBAL'` and reconciling `src/PlatynUI/core/runtime.py`'s process-wide `_RuntimeAccessor` singleton with per-suite isolation.
- **Windows/macOS parity.** Windows UIA (`thread_local` COM apartment) and macOS AX (main-thread affinity) adopting the per-runtime shape within their OS thread constraints. Phase 1 still fixes the Windows *highlight* bug as a side effect of removing that one global.

## Capabilities

### New Capabilities
- `runtime-session-config`: the construction-time `config` dictionary contract — the `platform`/`providers` grouping keyed by backend id, resolution precedence (config value over environment over auto-detect), the empty-config-equals-current-behavior guarantee, tolerant handling of unclaimed keys, and construction-time immutability.
- `per-runtime-platform-lifecycle`: each runtime owns and, on drop, releases its own platform instances; runtimes share no platform connection or global state; a runtime built after a previous one has been torn down establishes a fresh connection (the multi-suite guarantee), and a runtime bound by `config` connects to exactly the session it names.

## Impact

- **Affected specs:** `runtime-session-config` (new), `per-runtime-platform-lifecycle` (new).
- **Rust runtime:** `crates/runtime/src/runtime/mod.rs` (Runtime holds an owned platform bundle + `RuntimeConfig`, not `&'static` device refs), `platform_modules.rs` (**removed** — lease + `PLATFORM_MODULES_STATE` deleted), provider registry `create()` gains the per-provider config.
- **Rust core:** `crates/core/src/platform/` — new `PlatformFactory` trait + registration (mirroring `provider/` factories); device accessor `inventory` iterators for `&'static` devices give way to factory discovery. `RuntimeConfig` type + parse. **BREAKING** to the internal platform-registration API (the `register_pointer_device!`/`register_platform_module!` macros and their call sites in every `platform-*` crate change shape).
- **Rust platform-linux / -x11:** the X11 connection, keymap, atoms and highlight controller move from `static` into owned instances shared via `Arc`; the `platform-linux` mediator becomes a `PlatformFactory` that selects X11 vs Wayland from config/probe instead of routing through a global `RESOLVED`.
- **Rust platform-windows:** the highlight `OnceLock` controller becomes owned instance state (fixes the suite-2+ silent highlight death).
- **Rust provider-atspi:** `AtspiFactory::create` accepts a bus address from `providers.atspi.bus_address`, falling back to env (`connection.rs`). Additive.
- **Python/PyO3:** `packages/native/src/runtime.rs` — `Runtime(config)` accepts and parses the dict, and `new_with_mock()` routes through the mock backend; `_native.pyi` updated. `src/PlatynUI/BareMetal/__init__.py` — new `config=` import argument forwarded into `_create_runtime()`.
- **Other Rust runtime consumers:** `Runtime::new()` stays no-arg (empty config), so `crates/cli` (`lib.rs:144`), `crates/playground` (`main.rs:10`) and `apps/inspector` (`lib.rs:834`) are unaffected. `Runtime::new_with_factories_and_platforms` + `PlatformOverrides` are reworked as the lease is removed, touching `crates/cli/src/test_support.rs` and the native mock path (`packages/native/src/runtime.rs:697`).
- **Tests:** native unit tests for `RuntimeConfig` parsing/precedence/tolerance; a Python/RF mock suite for `config=`; the `just test-acceptance-x11` multi-suite lane becomes the regression guard (real AT-SPI/X11 — verifies isolation and reconnect-after-teardown, which the mock cannot).
- **Docs:** `dev-docs/architecture.md`, `platform-linux.md`, `python-bindings.md`, `python-library-design.md`, `testing-strategy.md`; `BareMetal` docstring; `docs/` as needed.
- **Native rebuild:** yes — platform/runtime changes are in the native binding; the Python/RF surface needs a `maturin` rebuild (via `just test-python` / `just build-native`).
- **Providers / support:** X11 + AT-SPI (real, Linux — the driver, verified against egui in the acceptance lane); Windows UIA highlight (real — fix compiled/clippy-checked from Linux, runtime-verified on a Windows host via a dedicated task); Wayland, macOS AX, mock — unaffected in Phase 1.
- **BREAKING:** none at the public RF/Python surface (the `config=` argument is additive and defaults to current behavior). Internal Rust APIs change shape — the platform-registration macros and the `new_with_factories_and_platforms` / `PlatformOverrides` constructor path — and their in-tree call sites (cli test support, native mock) are updated in the same change; no consumers outside this repo.
