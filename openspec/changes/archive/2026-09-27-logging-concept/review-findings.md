# Deferred findings of the logging review

The project-wide logging review behind this change confirmed 201 findings, and its verifiers added 25. This change implements the 26 of high priority that concern the library (tasks.md, section 5); the four about the Wayland compositor are listed under *Development tools outside the library*. An entry is dropped by a follow-up only when it carries a `Status:` line saying that this change implements or supersedes it; every other entry stays open, even at a location this change touches. A `Status:` line that says *partly implemented* keeps the entry for what it names as remaining, and one that says *open* keeps it and records how a maintainer decision changes it. The findings below are deferred to follow-up changes, one per area. Each entry is the verified version: location, proposed level, proposed message, and the reviewer's reason. Apply `dev-docs/logging.md` when implementing them; some entries predate the maintainer decisions recorded in design.md and must be adjusted to them: keyword lines at DEBUG; failed auto-activation at DEBUG; no lane-report tooling; decision 7, by which keyboard records that name keys or carry a device's error text are trace-level; unknown setting keys of an active component and unknown top-level buckets warn; Python loggers are `platynui.<module path>` through `logging`, keyword modules included; PlatynUI's Python code logs no diagnostic at INFO; a single level L means `warn,platynui=L`, and `error` and `off` apply to every module.
