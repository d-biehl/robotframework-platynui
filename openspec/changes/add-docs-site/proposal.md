# Proposal

## Why

PlatynUI has no user documentation yet. `docs/` is reserved for it and holds only a README and a talk. What a Robot Framework user needs to know lives in three places, none of which teaches:

- the Libdoc of `PlatynUI.BareMetal`;
- the root README;
- the READMEs of the CLI and Inspector packages.

The Libdoc is a precise reference and stays the contract for every keyword. It does not walk a reader from installation to a first test, explain the concepts behind locators and waiting, or show how to handle tables, dialogs or applications started through a launcher.

A website built from Markdown in the repository can do that, and its examples can be run as tests, so they cannot silently go stale.

## What Changes

- **A documentation website in `docs/`,** built with Astro and Starlight, for Robot Framework users (not PlatynUI developers), in English. It has a fixed structure:
  - Getting Started, Concepts, Guides, Tools, Reference, Troubleshooting;
  - a landing page and the first pages of Getting Started (what PlatynUI is, installation).

  The remaining content follows in later changes and commits; this change sets the frame it is written in.
- **Writing rules for the site** in a developer doc:
  - audience and voice;
  - the four page types (tutorial, guide, concept, reference);
  - how examples are written;
  - platform-neutral wording;
  - no status or roadmap text;
  - one home per fact;
  - the Libdoc docstrings as the contract the site links to instead of copying it.
- **Robot Framework syntax highlighting** with RobotCode's TextMate grammar, vendored into the docs project.
- **Internal links are checked** on every build. A broken link fails the build.
- **Examples are tested:**
  - Robot Framework examples live as real `.robot` files under `docs/examples/`.
  - Pages include them from there, never as copied snippets.
  - They run in the real-provider acceptance lanes against the demo application from `add-demo-app`.
- **Local workflow:** `just` recipes to serve, build and check the site.
- **CI:**
  - The site is built on every pull request.
  - It is deployed to GitHub Pages from `main`.
  - The site URL and base path are derived from the repository at build time. The repository will move back to its original location, so neither may be hard-coded.
- **The keyword reference is reserved, not generated here.** The Reference section gets its place in the structure. Its keyword pages will be generated by RobotCode's upcoming Markdown generator for Robot Framework library documentation, not by Robot Framework's `libdoc` tool, in a later change.
- **Pointers updated:** the root README, `docs/README.md` and CONTRIBUTING.md point to the site and the writing rules.

## Capabilities

### New Capabilities
- `user-docs-site`: the user documentation website. It covers where it lives and how it is built; its section structure; highlighting, link checking and tested examples; local recipes; CI build and GitHub Pages deployment with a derived URL; and the reserved keyword reference.

### Modified Capabilities
- None.

## Impact

- **New toolchain:**
  - Node.js with npm, used only inside `docs/`.
  - `just check`, `just test` and the native build stay free of Node.
  - Contributors who do not touch the site need nothing new.
- **New files:**
  - the Astro project in `docs/` (configuration, content collection, the RobotCode grammar, the first pages);
  - `docs/examples/` with the first tested example;
  - `dev-docs/user-docs.md` with the writing rules;
  - a GitHub Actions workflow (or jobs) for building and deploying the site.
- **Changed files:** `justfile` (docs recipes), `docs/README.md`, root `README.md` (link to the site), CONTRIBUTING.md (docs section and recipes), `dev-docs/README.md` (index).
- **Tests:**
  - The docs build with the link check is a CI gate for pull requests.
  - The examples run in the existing acceptance lanes. They need the non-mock native build and the demo app, so they depend on `add-demo-app`.
  - No Rust, no Python library code and no native bindings change; no native rebuild.
- **Platforms:** the site itself is platform-independent. Its examples run where the acceptance lanes run (Windows, Linux X11, the PlatynUI compositor).
- **Repository settings:** GitHub Pages has to be enabled with "GitHub Actions" as its source. This is a one-time setting outside the code, and it has to be done again after the move.
- **Dependencies:**
  - Tested examples need `add-demo-app`.
  - The keyword reference needs RobotCode's Markdown generator.
  - Everything else is independent of both.
- **BREAKING:** none.
